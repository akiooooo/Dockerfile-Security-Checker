## Демонстрационный корпус

Ожидаемые результаты заданы в `examples/manifest.json`. Сравнение выполняет `scripts/evaluate.py`; повторяющиеся нарушения одного правила в одном файле считаются одной парой.

| Показатель | Значение |
| --- | --- |
| Dockerfile | 18 |
| Ожидаемые и найденные пары «файл — правило», TP | 58 |
| Неожиданные пары, FP | 0 |
| Пропущенные ожидаемые пары, FN | 0 |
| Precision на этом корпусе | 100% |
| Recall на этом корпусе | 100% |

Эти показатели означают совпадение с эталоном на небольшом наборе, который использовался при разработке. Они **не означают нулевой процент ошибок на произвольных Dockerfile**. Нет независимой контрольной выборки, разметки нескольких экспертов и оценки всех возможных shell-конструкций.

Регрессии ложных срабатываний проверяют, в частности: номер порта registry вместо тега; scratch; digest вместе с latest; root в builder; безопасный унаследованный USER; `.env.example`; TOKENIZER вместо TOKEN; опасные слова внутри echo; кеш pip через ENV и BuildKit; npm install в builder; унаследованный HEALTHCHECK. Сложный shell и анализ состояния внешних базовых образов остаются ограничениями.

Собран образ `dockercheck-local`. CLI успешно проанализировал собственный Dockerfile из read-only mount и вернул JSON с двумя информационными рекомендациями и кодом 0.

Собран и запущен `examples/good/python`. HTTP-запрос с хоста и из контейнера вернул 200. Проверена конфигурация пользователя `10001:10001`; ручной запрос из HEALTHCHECK также выполнился успешно. Временный контейнер после проверки остановлен.

Остальные 17 примеров проверялись статически; их сборка и запуск не заявляются. Плохие примеры намеренно содержат рискованные паттерны и не должны запускаться как готовые приложения.

## Что остаётся для дальнейшей работы

- Независимый корпус реальных репозиториев, проверка разметки несколькими людьми.
- Поддержка более полного shell AST и современных Dockerfile frontend-возможностей.
- Автоматическая проверка отчёта по полной SARIF JSON Schema; сейчас тестируются ключевые поля, а не вся схема.
- Семантика `.dockerignore`, Dockerfile-specific ignore и более точное раскрытие ARG/ENV.
- Пагинация/потоковое чтение не нужны обычному Dockerfile, но ограничения на очень большие входные файлы можно добавить отдельно.
- Проверка совместимости Python 3.11 и 3.13 на удалённой CI-матрице; локально фактически проверен Python 3.12.
